## Frozen CLI contract

The actual [download leaf](../../internal/cli/commands/fanbox/download/download.go) has minimum one variadic source and no local options except Cobra help. Inherited native `--proxy`/`--no-proxy` options remain available, including before the leaf. Changing both flags conflicts even when `--no-proxy=false`; true no-proxy supplies an explicit empty override. Saved FANBOX options retain native proxy/user-agent and independent solver configuration. There is one client for the whole command and no Pixiv-account fallback or pool replay.

The ordinary [TextValue pipeline](../../internal/cli/pipeline/pipeline.go) reads all non-TTY stdin as one source only when positional sources are absent, removes exactly one terminal LF or CRLF, and preserves a bare CR, other whitespace and internal newlines. Explicit sources never read stdin. There is no word splitting, record/NDJSON sniffing or `-` stdin sentinel. Input-read failure is an input usage error; missing source is the ordinary `usage: pixiv fanbox download SOURCE...` error.

The Rust command's public source representation is `Vec<String>`. Its stdin source and decoded URL-path handling use `from_utf8_lossy`; Go can carry arbitrary byte strings. Invalid UTF-8 stdin and invalid UTF-8 URL-path bytes remain explicit representation debts. The recorded valid-string observations do not establish arbitrary-byte parity.

Source classification reuses [PostsFetch](../../internal/cli/commands/fanbox/post/post.go) and the real [ResolveURL parser](../../sdk/fanbox/reference.go). Exact lowercase `http://` or `https://` prefixes select URL resolution; accepted post/tag/creator references select `Post`/`TaggedPosts`/`CreatorPosts`. Nonempty ASCII-digit sources select a post; other text selects a creator before downstream validation. Sources are not silently trimmed or reclassified first. This is not a direct-media downloader or a feed/all-creators command.

[AllResults traversal](../../internal/cli/commands/fanbox/internal/listing/listing.go) visits every cursor page, including empty intermediate pages, checks context before fetching, rejects a repeated opaque cursor and stops at the first fetch/consumer failure. Sources/pages/posts/assets run sequentially. Whole-batch decoding precedes any save from that batch. Files already published by an earlier batch, post, asset or source remain after a later failure.

There are no download JSON/NDJSON/report/record/template/page/limit/on-error switches, no automatic machine-readable output selection, metadata sidecars or whole-run rollback/resume. Output/template configuration does not add these options to the actual leaf. The general migration strategy's CLI feature list is not evidence that every command exposes every feature. Removing previously invented Rust download flags restores the frozen Go surface; it does not remove Go functionality.

Real Go help performs three writes of 44, 1 and 254 bytes and ignores each writer result before any root hooks, stdin or requests. The three appended error/short-write/EPIPE observations return 8/0/0 bytes, leaving stdout `Download`, empty stderr and exit 0. The former Rust one-write helper was a source-inspected mismatch; normal production help now uses the corresponding three-emission command path rather than test-only chunk reconstruction. The four subsequent Go observations fix the actual pflag shorthand surface: `-hh` prints ordinary help, `-hx` fails with unknown `-x` and exit 2, and `-h=false`/`-hh=false` with source `123` execute the ordinary saved download. ## Body, asset order and destination names

The real [wire mapper](../../internal/services/fanbox/endpoint/post/wire/wire.go) chooses a non-nil images list, otherwise a non-nil files list, otherwise blocks. An explicitly empty list still wins. Missing blog map references and invalid asset identities/locators fail before the CLI. The [SDK mapper](../../sdk/fanbox/ops.go) merges images first, then files; block-only additions are deduplicated by ID per kind, while explicit-list duplicates remain. Mixed blog display order is therefore not the save order. Duplicate opaque identities can share the last cached locator even when their original filename extensions differ; the oracle preserves the resulting request/file bytes.

Only a nil body skips a post. A restricted post with a non-nil body still saves; non-nil empty/text/embed-only bodies still validate path identity and create the post directory. Text/article/video/unknown blocks, thumbnails and covers are not CLI save targets. Creator icon/cover remain supported public SDK save resource identities alongside post image/file.

Destination layout is `DOWNLOAD_PATH/fanbox/CREATOR_ID/POST_ID/ASSET_NAME`. Every component uses Go `TrimSpace`, substitutes `_` for `/\\:*?"<>|`, rejects empty/dot/dot-dot and undergoes lexical joined-path containment. A nonempty asset name wins before sanitization; whitespace-only names fail instead of falling back. Otherwise use asset ID plus lowercased URL-path extension, accepting 2..12 bytes including the dot and ignoring query/fragment. This is not MIME extension correction, reserved-device-name handling, trailing-dot/control cleanup or symlink-aware containment. A NUL-containing nonempty filename is retained through naming, opens/streams media and fails at late publication on the captured Linux filesystem.

One full-path dedup set spans all sources/pages; a path is marked before its save and repeated sanitized paths are skipped. An existing destination file is not a skip condition. The zero-resource-ref skip and empty-ID `asset`/`asset+extension` fallback branches exist in direct helpers, but real endpoint DTO validation rejects empty IDs/locators first. Arbitrary nonzero asset-kind DTO behavior is likewise helper-only. These branches are not claimed as reachable root observations, and no fabricated DTO is substituted to claim coverage.

## Public SDK save, atomic state and ownership

The genuine [SaveResource implementation](../../sdk/fanbox/resource.go) rejects trimmed-empty destination paths before opening. It obtains GET media through the existing opaque-reference cache/re-resolution and first-party media policy. Open failures keep their operation/classification. A response returned to save must be 2xx; returned 304 is a `SaveResource` UpstreamError. Body-read, atomic-write and cooperative cancellation failures become `SaveResource` LocalStateError with safe cause `cannot write resource`; the underlying cancellation cause is not retained. The deferred media body Close runs and its error is ignored. Metadata/open failures can have earlier, separately captured close/error precedence.

The six URI rows retain actual Go request-object serialization: literal Unicode path/fragment and fragment spaces are escaped; lowercase `%2f`, valid raw percent-escape spelling, reserved fragment characters and Unicode RawQuery retain their observed spelling. The shared production escaped-path/fragment correction is not an observation projection. These are custom HTTP request URL/RawRequest observations, not evidence that native HTTP wire request targets transmit fragments or that arbitrary URI grammar is equivalent.

Successful `SavedResource` contains Path and Size with empty ContentType even when the response has MIME. Progress contains cumulative Done and zero Total, for every positive read before writing those bytes, including positive bytes accompanied by an error. Exact EOF succeeds; wrapped EOF and other read errors do not become success.

The actual [atomic writer](../../internal/storage/file/atomic/atomic.go) creates absent parents at 0700, uses a private same-directory temp, reads 64 KiB chunks with context checks before reads, writes positive bytes before handling read errors, then syncs, closes, chmods 0600 and renames. CLI-created directories are 0755 subject to umask, and are not subsequently remoded by the SDK. A failed normal save removes its temp and preserves old final contents. Created directories and previously successful files remain after later failures; there is no transaction across assets.

Two unusual captured source behaviors must remain explicit:

1. Cancellation triggered by positive bytes accompanied by exact EOF still publishes successfully: no subsequent context check precedes sync/rename. The CLI oracle captures the corresponding successful saved line and exit.
2. An owned progress callback can replace the temp pathname with an empty directory. With no existing final, chmod/rename can publish that directory. Cleanup uses nonrecursive `os.Remove`, not recursive tree deletion. The old-final/blocker variants preserve their separately observed outcome. This is actual temp-namespace source behavior, not proof of secure race containment.

The two panic cases recover outside the real save call, observe deferred media Close/temp removal and compare actual panic effects. They do not establish Go OS file-handle closure during panic, Rust asynchronous future-Drop close, or arbitrary concurrent read/close equivalence.

The CLI emits `saved: PATH\n` only after successful publication. Its `fmt.Fprintf` error/short-write/EPIPE results are ignored; synthetic writer faults therefore allow later saves and a successful exit unless another error occurs. This does not prove OS signal/SIGPIPE behavior. Normal root usage errors exit 2, startup/save/cleanup failures exit 1, and cleanup errors are joined in their observed order.
