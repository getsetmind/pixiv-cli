Each producer uses owned synthetic data and bounded local TLS HTTP/1 peers or injected HTTP ports. Logical official hosts are redirected by an exact local dial allowlist. Trust is installed only in the owned transport, not in the OS. No real credentials, accounts, media, registry/browser state or external destination is accessed. Go nil/pointer identity is not represented as a portable Rust promise.

The ordinary CLI always supplies a caller-owned HTTP client through its resolved proxy route, including an empty override. An unconditional native close on Execution teardown would change that behavior. Auth with absent HTTP override instead uses the SDK-owned default route. CloseIdleConnections is repeatable and nonterminal, and must be ownership-aware at every adapter.

## Least-divergent ordinary transport route

[Official source receipts](provenance/ordinary-transport-official-sources.json) seal exact reqwest 0.13.5, hyper-util 0.1.21, hyper 1.12.0 and h2 0.4.14 archive bytes, VCS metadata, licenses and every archive file. Existing registry sources were not edited. Official h2 was downloaded and inspected outside the repository; no dependency is activated here. The separate FANBOX Chrome146 TLS/header/decoding policy is not an ordinary transport substitute.

The initial implementation boundary is reqwest plus hyper-util HTTP/1: retain a genuine underlying pool control handle before reqwest service layering, atomically remove current idle HTTP/1 entries and set the future-idle flag, preserve pending waiters, deliver available connections to waiters before rejecting leftover idle insertion, and clear the flag once on a new acquisition. Active bodies finish normally. Sender retirement alone does not prove physical peer shutdown; driver completion and peer observations are separate.

Go failed Open and owner-drop retention must remain genuine pool ownership. Official Go idle TTL starts at each actual idle return. Current hyper-util weak pool references instead close the pool when the last client drops. An outer-client timer starting at Drop/Open error is not equivalent. A proposed ordinary policy retains the actual pool through active leases and individually cancelable idle-entry expiry tasks, keyed by entry ID and actual idle timestamp; checkout, explicit close and dead-driver removal release those guards. The existing coarse periodic scanner cannot claim exact per-entry deadline semantics. Go defaults of two idle connections per host and 100 globally differ from reqwest's current unlimited per-host pool, and remain implementation obligations.

HTTP/2 is a separate activation boundary: current ordinary reqwest features omit HTTP/2. Source inspection requires one atomic h2 stream-mutex gate checking reserved admissions and genuinely nonclosed streams, using Stream::is_closed including pending outbound frames/data. Busy/reserved close attempts make no state change or future-close flag. Fallible shared-pool admission must be carried through hyper dispatch and retained locally until real stream creation; h2 clears request Extensions before locking, so leaving admission only in Extensions is unsafe. Driver retirement needs a wake, a Pending recheck, physical flush/shutdown and completion evidence. HTTP/2 TTL must follow real busy-to-idle transitions. These are source-driven design constraints, not native HTTP/2 execution evidence.
