## Build version, command entry and output

[buildinfo.go](../../internal/shared/buildinfo/buildinfo.go) defaults exactly to `Version="dev"`; only that exact string is development. The Go root reads this same source and prints `pixiv VERSION\n`. Signed candidate preflight requires `pixiv TAG\n`, including the leading `v` and exactly one newline. Actual root observations preserve release/dev/prerelease-build output and duplicate-last boolean flags. An explicitly empty build Version disables Cobra's built-in version flag, so --version becomes usage exit2. Malformed current update versions and root error envelopes come from actual RunContext rather than inference from a release tag.

[The update command](../../internal/cli/commands/update/update_cmd.go) has no aliases or positional/stdin input. Local flags are `--check=false`, `--prerelease=false`, `--json=false`, `--proxy=""`; there is no update-local `--no-proxy`. `--json` requires `--check`. Exact-argument usage is `pixiv update [--check] [--prerelease] [--proxy URL]`. Parse/Args rejection precedes startup. Valid entry runs pending cleanup and persistent-handler policy, ensures config/diagnostics, then loads ordinary runtime settings. Update needs no account or database. A runtime-load error is wrapped with `load update configuration: ` before construction.

Effective proxy is runtime HTTPSProxy unless the flag is Changed, including explicit empty. [Production construction](../../internal/cli/commands/update/production.go) uses the ordinary unauthenticated Go HTTP transport, disables environment proxy and enables embedded public-source races exactly when the effective proxy is empty. HTTP(S)/SOCKS proxy parsing and ordinary redirects are not SDK-specific redirect/trust/pacing rules.

Text output is exactly four newline-terminated fields: `source: SOURCE`, `current version: CURRENT`, `latest version: LATEST` (`none` when nil), `update available: yes|no`. JSON is Go's indented object with `source`, `current_version`, `latest_version`, `latest_prerelease`, `update_available`; absent candidate is `latest_version:null`. The root's Changed `--json=false` error-envelope selection is distinct from update's JSON-success boolean. Startup failures bypass JSON. ## Source detection and explicit policy

[Install source detection](../../internal/update/installer/install_source.go) returns development before executable/environment/filesystem/build-info reads when the version is exactly dev. For formal builds it resolves executable symlinks, recognizes Homebrew `Cellar/<formula>/<version>/bin/pixiv[.exe]` with validated `INSTALL_RECEIPT.json` `.rb` source identity, then checks the Go main-module identity and the resolved GOBIN or first GOPATH/bin/default official GOPATH executable. Windows uses EqualFold after filepath cleaning. Missing expected Go executable allows release fallback; other resolver/receipt failures are errors. All five source values remain development, homebrew-stable, homebrew-beta, go-install, release.

Go `debug.ReadBuildInfo` has no automatic Rust-native equivalent. The future Rust implementation must explicitly document the Go-install source provenance mapping; an injected source detector does not prove that a Rust executable can discover Go module metadata. Do not introduce a source-override flag or silent Go fallback to hide this obligation.

[Coordinator Execute](../../internal/update/coordinator.go) detects source before parsing current SemVer, rejects development before queries/commands, then checks with Automatic=false and requested prerelease inclusion. A newer candidate is decided by SemVer precedence, ignoring build metadata. `--check` returns before every command or installer. Nil/equal/older candidate is a no-op for go-install/release, while an explicitly requested Homebrew channel switch sets update_available=true even for absent/older candidates.

Same-channel Homebrew always runs `brew upgrade FlanChanXwO/tap/pixiv-cli` or `.../pixiv-cli-beta`, even without a newer candidate. ## Version, release query and cache

[Canonical SemVer](../../internal/update/release/version_policy.go) requires leading `v` and three decimal components with no leading zero. Numeric identifiers have no integer-size limit; compare decimal strings by length then bytes. Prerelease/build identifiers use ASCII letters/digits/hyphen; numeric prerelease has no leading zero. Stable follows prerelease, numeric prerelease sorts before alphanumeric, and build metadata is retained in archive names while ignored in precedence.

[Release Check](../../internal/update/release/release_client.go) queries the fixed repository API with GET and `User-Agent: pixiv-cli`, follows all valid next Link pages and uses per-page If-None-Match. Validate scheme/host/userinfo equality, normalized endpoint path, no fragment, Link syntax, unique next links, canonical pagination loops and duplicate cached page identity. Query spelling is not generally canonicalized: captured malformed raw percent query is accepted by Go's URL handling. Cache URLs remain canonical API URLs when network requests use a mirror.

Drafts are excluded. Stable skips GitHub-labelled prerelease before tag parsing, then skips semantic prerelease. Included published invalid tags fail instead of choosing an older valid release. Highest SemVer wins and first equal-precedence release wins, with assets copied unchanged. Page JSON accepts its first value despite trailing bytes; the source API probe instead requires one non-null root array decoded into the minimal probe struct and EOF. Captured `[null]`, `[{}]` and null known fields are accepted; the probe does not require a present tag or valid SemVer. A first JSON value returned together with a reader error is preserved where the decoder already succeeded. Query/probe/download Body.Close errors are ignored; decode/read failures at their actual boundary remain errors.

Default cache is `~/.pixiv-cli/cache/github-releases.json`. Schema2 stores releases/assets, checked_at and per-page URL/ETag/next_url/releases. Missing cache is allowed; malformed JSON, missing checked_at or port errors fail. Old schemas do not reuse pages/304; 304 without the exact cached page fails, and cached next is revalidated. Automatic Check adds one total three-second child deadline across cache/source/query/write and throttles schema2 while now < checked_at+24h, including future checked_at. Explicit update has no artificial three-second deadline and is unthrottled. Successful selection precedes save; checked_at uses captured pre-fetch time and serialized cache ends in newline. There is no added context post-check after a successful cache.Write.

[Physical file cache](../../internal/update/installer/release_cache.go) creates/tightens Unix directory0700, writes a same-directory temp0600, writes/syncs/closes, then platform replaces. Windows directory creation does not prove POSIX-style ACL privacy. Ordinary failure cleans the temp; unresolved replacement recovery preserves it through the wrapped/Joined marker. Actual bytes/mode and replace-seam state are observed, while arbitrary sync/close/permission/race faults remain unproved.
